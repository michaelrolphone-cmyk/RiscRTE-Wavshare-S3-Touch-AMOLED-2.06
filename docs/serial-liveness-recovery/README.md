# Waveshare 0.1.59 serial liveness recovery

This additive recipe preserves the released 0.1.58 inputs and all earlier recipes.
The user's installed 0.1.58 produced an NS deadline error and a Home return marker;
no completed namespace response or file write was observed. The physical cause is
not conclusively established.

Runtime 0.4.11 serves RAM-only protocol metadata during native settings ownership,
returns bounded clean BUSY for storage admission, and records bounded first/deadline
observations. Shared Home defers phase3 paired confirmation while its sampled
checkpoint is BUSY, preserving input/render/yield and the native strict storage
veto. A single RAM-only first-exit checkpoint identifies the first outer route.

The complete native settings/serial composition tests metadata, strict confirmation
refusal/recovery and guarded create/replace/readback at 1/8/16/32 ms service cadences.
Held-worker and 50 ms cases fail safely with clean BUSY and disconnect/drain checks.
All 12 normal/ASan+UBSan cases passed. Sector transport, NVS and scheduler timing are
modeled; target execution and physical recovery remain separate.

Its 28 confirmation controls and 12 checkpoint runs cover both watch display sizes.

The final store replaces Home ELF/manifest, cohort metadata and the catalog ELF's
versioned core-feed URL. Its unchanged manifest is included in the exact replacement
lock. All other 107 internal files and all 45 external files remain byte-identical.
Five essential applications and 38 providers remain internal; 22 application ELFs
remain on SD. Boot policy, grants, namespace12 mapping and hidden clock shim stay
unchanged. Pre-native packing leaves 791 empty blocks in the existing partition.

The installed .58 serial failure requires corrected firmware first, then an explicit
reconnect to .59, preflight and per-file transfer/readback. Known shipped LoRa paths
use three previous-hash-guarded replacements and 42 creates. No SD clearing occurs.
Unrelated paths and app data are outside the write set. Any existing target or prior
hash mismatch stops preflight for explicit reconciliation. The full factory image
erases internal application data; post-install preferences must be tested separately.

Publication uses the exact same-run native artifact, immutable public byte audit,
real GitHub release ID, initial catalog revision1 and revision-checked canonical
association. No availability or hardware success is claimed before those checks.
